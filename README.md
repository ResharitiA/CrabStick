# Анализатор рисков оттока

FastAPI-сервис для поиска клиентов, которым требуется внимание: рассчитывает объяснимый risk-score, показывает причины риска и оценивает потенциальные потери в евро.

## Запуск

Требуется Docker с Docker Compose.

```bash
docker compose up --build
```

Откройте <http://localhost:8000>. Демонстрационные данные загружаются при первом создании тома PostgreSQL.

По умолчанию:

- логин: `admin`
- пароль: `change-me`

Перед публичным запуском задайте собственные значения:

```bash
APP_USERNAME=analyst APP_PASSWORD='strong-password' SESSION_SECRET='long-random-secret' docker compose up --build
```

В PowerShell переменные можно задать через `$env:APP_USERNAME = "analyst"` и аналогично для остальных. Чтобы заново создать БД из SQL-файлов, остановите Compose и явно удалите том командой `docker compose down -v`; это удаляет все настройки и загруженные данные.

## Модель риска

Для каждого клиента рассчитываются нормированные сигналы от 0 до 1:

- близость окончания услуги;
- отключённое автопродление;
- `prolong_wait`;
- недостаток доступных средств;
- непокрытая балансом доля продлений;
- неуспешные и отсутствующие успешные транзакции продления;
- доля `suspended`, `blocked` и `deleted` услуг.

Вклад признака равен `signal × weight`; итоговый score — сумма вкладов, ограниченная диапазоном 0–100. Пороги по умолчанию: низкий риск ниже 35, средний от 35, высокий от 65. Клиент без услуг получает статус `not_assessed`, а не искусственный нулевой score.

Доступные средства — основной баланс плюс бонусный баланс только при `bonusState=unlocked`. Все денежные поля хранятся в евроцентах: 100 единиц = €1.

Потенциальные потери считаются для продлеваемых услуг в горизонте модели:

```text
exposure × score / 100 × (1 − 0.5 × coverage)
coverage = min(spendable_balance / exposure, 1)
```

Так оценка учитывает стоимость услуг и риск, а достаточный доступный баланс снижает ожидаемые потери максимум на 50%: он не обнуляет риск добровольного отказа при выключенном автопродлении.

Все веса, пороги и горизонт редактируются в панели. Настройки лежат в таблице `model_settings`, поэтому сохраняются после перезапуска. Панель обновляет данные каждые 10 секунд и сразу после изменения коэффициентов — reload страницы не нужен.

## Архитектура

- `app/main.py` — HTTP API, сессии, агрегация и Prometheus.
- `app/risk.py` — чистая объяснимая модель скоринга.
- `app/db.py` — PostgreSQL-репозиторий и атомарная замена снимка.
- `app/schemas.py` — DTO и проверка входных данных.
- `app/static/` — адаптивная панель без отдельного frontend build.
- `001_schema.up.sql`, `002_seed.sql` — схема и тестовый снимок.

Расчёт выполняется из текущих данных при каждом запросе, поэтому после `PUT /api/v1/source/snapshot` дополнительный job пересчёта не нужен.

## API

Обязательные маршруты:

- `POST /api/v1/auth/login`
- `GET /api/v1/auth/me`
- `POST /api/v1/auth/logout`
- `GET /api/v1/customers`
- `GET /api/v1/customers/{id}`
- `GET /api/v1/analytics/summary`
- `GET|PATCH /api/v1/model/settings`
- `PUT /api/v1/source/snapshot`
- `GET /metrics`

Список клиентов сортируется параметрами `sort_by=id|email|balance|totalReplenished|score` и `sort_order=asc|desc`. Также доступны `risk_level`, `search`, `offset`, `limit`.

## Как добавить новый признак

1. Добавьте ключ и начальный вес в `DEFAULT_WEIGHTS` в `app/risk.py`.
2. Рассчитайте значение 0–1 в словаре `values` и добавьте человекочитаемую подпись в `FEATURE_LABELS`.
3. Добавьте тот же ключ в JSONB начальных настроек в `001_schema.up.sql`.
4. Добавьте UI-подпись в объект `labels` в `app/static/index.html`.
5. Покройте влияние признака тестом в `test_risk.py`.

JSONB позволяет добавлять коэффициенты без изменения структуры таблицы.

## Проверка

Без Docker можно проверить генератор, модель и API (Python 3.10+):

```bash
python -m pip install -r requirements-dev.txt
python -m unittest -v test_generate.py test_risk.py test_schemas.py test_api.py
```

После запуска Compose демонстрационный сценарий: войти, открыть клиента из рейтинга, проверить вклад признаков и потери, изменить вес, увидеть новый рейтинг без reload, затем открыть `/metrics` и Swagger.
